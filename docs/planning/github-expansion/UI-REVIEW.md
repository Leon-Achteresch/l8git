1. **P1 — CI Agent tab render loop.** `src/components/repo/github-ci/ci-agent-task.tsx:26`: `useRepoStore(s => Object.keys(s.repos))` returns a fresh array for every external-store snapshot. With Zustand 5 / React 19 this produces an unstable snapshot and maximum update depth error. Reviewer isolated native Playwright reproduction observed 54 renders and the error. Proposed fix: stable repo-object selector plus memoized keys, or shallow equality.
2. **P1 — Unreviewed PR head can merge.** `src/lib/change-workflow-ui/initiative-ops.ts:49`: a push between `pr_detail` and `pr_merge` is not prevented server-side; read-back detects it only after the new commit has merged. Reviewer reproduced A checked / B merged / no expected-SHA payload. Proposed fix: carry expected SHA through the backend merge contract to the provider's conditional merge API, rejecting drift before mutation.
3. **P2 — Stale workflow input schema.** `src/components/repo/github-ci/ci-dispatch.tsx:55`: changing workflow or ref while A's inputs are loading allows A's late result to mark B ready with A's fields/defaults. Proposed fix: request identity and pre-dispatch workflow/ref identity checks; reject stale results.
4. **P2 — CI agent context/worktree can cross runs.** `src/components/repo/github-ci/ci-agent-task.tsx:84`: resets do not invalidate pending A context/worktree responses after switching to B. Proposed fix: bind responses and send preflight to run/attempt/job, or remount by that identity.
5. **P2 — Stale narrative patch cache.** `src/components/repo/change-workflow/review-narrative-panel.tsx:30`: clearing the cache after head change does not cancel old promises; old-head patch results can overwrite the new map and incorrectly mark an anchor current. The existing `pr_file_patch` response is not pinned to the displayed SHA either. Proposed fix: revision-bound request generations plus validate actual loaded revision.
6. **P2 — Refresh leaves artifact/deployment data stale.** `src/components/repo/github-ci/github-ci-extensions.tsx:143`: top refresh reloads runs/jobs, but retained run object identity means artifact/deployment effects do not re-run. Freshness timestamp can advance despite stale panels. Proposed fix: pass refresh generation to those panels and their loaders.
